# B7b-2: Expression Continuations Across `#if` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An `#if` group may stand anywhere inside an AL expression that alc accepts (tail, nested and consecutive
groups, `in`/`is`/`as` continuations, every expression slot, whole operands, leading prefixes), each with a tree
that follows the transparent-region contract and is oracle-validated or assertion-pinned, and no production tree
changes.

**Architecture:** Phase 0 records alc evidence, freezes the scoped manifest, and runs an attachment spike that
proves every tie-break before any grammar change. Phase A closes the tail and replaces the oracle's tail and prefix
assemblers with one region assembler. Phase B gives every expression slot a tail through one helper. Phase C adds
operand groups. Phase D documents. Each phase ends with a phase-gate task.

**Tech Stack:** tree-sitter 0.27 grammar DSL (`grammar.js`), Python tools (`tools/b7_audit`, `tools/config_oracle`,
`tools/perf`), alc 18.0.41 via `tools/alc_probe`.

**Spec:** `docs/superpowers/specs/2026-10-20-b7b-2-expression-continuations-design.md` (rev 3, approved 2026-10-20,
with the transparent-region contract as a user decision). §N refers to it. Read the whole spec before your task; it
is the binding authority. Where your task's measurement forces a deviation, record it in the spec's "Execution
amendments" section (create it at the end of the spec on first use) and report it; do not deviate silently.

## Review Focus

1. **Comments inside and around groups** (`r := 1 // c` newline `#if X` newline `+ 2 /* c */` newline `#endif;`) must
   parse as the tail with the comments as extras, oracle pass (Task 4 fixture `tail with comments`).
2. **`#elif` arms and groups without `#else`** in tails and operand groups (`r := 1 #if X + 2 #elif Y * 3 #endif;`,
   `r := 1 + #if X 2 #elif Y 3 #else 4 #endif;`) must parse and lower per configuration, including the no-arm
   configuration of a tail (valid) and of an operand group without `#else` (invalid, `contract-shape`) (Task 4
   fixture `tail with elif`, Task 10 fixture `operand group with elif`, Task 5/11 tests).
3. **Case-insensitive keyword operators** (`AS`, `In`, `iS`) in a tail must give the `as_keyword`/`in_keyword`/
   `is_keyword` operator and win over the torn call reading (Task 4 fixture `keyword operator spellings`).
4. **An incremental edit that turns a tail into an argument group and back** (insert / delete `,` right after
   `#if X` in `Foo(1 #if X + 2 #endif)`) must give the fresh tree (Task 4 test
   `test_incremental_tail_argument_edits`; Task 10 the same for an operand group: insert / delete the `+` after
   `#endif`).
5. **A tail inside a statement group's arm** (`#if A` newline `x := 1 #if B + 2 #endif;` newline `#endif`) and
   quoted/member operands (`x := Rec."No." #if X + Rec.Count() #endif;`) must parse clean with `has_error` False
   (the scanner depth counter sees two levels) (Task 4 fixture `tail inside statement group`).
