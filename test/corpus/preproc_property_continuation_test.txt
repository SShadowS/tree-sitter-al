A property value continued across a #if boundary
--
NOT alc-justified, and the claim that was here before was wrong.
.
The original note said alc ACCEPTS this. It does not: flat `MinValue = 1 + 2;`
REJECTS with AL0104 (';' expected) -- property values are literal, not
expressions. The earlier ACCEPT came from a broken probe method: alc DOES NOT
PARSE INACTIVE BRANCHES, so compiling a split file with the symbol UNDEFINED
certifies only the active branch and says nothing about the fragment. Proven by
a control -- `banana banana banana` inside `#if FOO` is ACCEPTED undefined and
REJECTED defined. Any split-file probe must compile BOTH ways
("preprocessorSymbols" in app.json), and flat-inlined as well.
.
What this fixture pins is therefore surplus tolerance, not conformance: we parse
a shape alc rejects. That is the deliberate parse-structure-don't-validate
choice and is harmless, but it must not be cited as compiler-backed.
.
The tail is a REQUIRED part of a separate `_property_value` alternative, not an
optional suffix. That is load-bearing. An optional tail overlaps every simple
value form (integer, decimal, ...) and is a reduce/reduce at `;`; attaching it
to `property` itself made the tail BEAT preproc_conditional_option_members and
turn a correct option_member_list into an ERROR. Requiring the tail means the
alternative does not exist at all unless a #if actually follows, so it cannot
race the rules that already read those directives.
.
BC.History stayed at 0 errors through BOTH broken attempts -- only
option_members_included_permission_sets and the TableRelation-semicolon fixture
ever saw them. An error count is not a correctness check.
