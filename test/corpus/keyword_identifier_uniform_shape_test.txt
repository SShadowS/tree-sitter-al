All thirteen keyword_identifier spellings produce the SAME node shape
`keyword_identifier` accepts thirteen words. Six were named `*_keyword` rules and
seven were bare `kw()`. A bare kw() is a token(PATTERN), which tree-sitter renders
as a HIDDEN symbol, so one node type had two shapes decided purely by which word
the source used: `Codeunit.Run()` gave `(keyword_identifier (codeunit_keyword))`
while `Record.Get()` gave a childless `(keyword_identifier)`. It was never a byte
gap -- `keyword_identifier` covers the bytes either way -- which is why the
query-coverage harness reported nothing and it outlived the losslessness work.
.
UNLIKE the object_type_keyword fixture beside it, this file really does pin the
shape. The children here are NAMED nodes, and corpus expected trees show named
children; that fixture's children are anonymous, which expected trees never show.
So deleting any `(*_keyword)` line below fails this test, and that is the
assertion. Verified failable by renaming one child to `(bogus_keyword)`.
.
The seven conversions are `alias(kw(w), w)`, which does NOT change what the token
matches -- kw(w) is token(RustRegex('(?i)w')) and alias() wraps that same token.
No spelling moved between `identifier` and `keyword_identifier`. The kwCases()
whitelist argument does not apply: kwCases() exists to stop kw() from WIDENING a
compound keyword over spellings AL uses as identifiers, and nothing here widens.
