; B7b-3 Task 6 negatives for case-branch separators (spec 4.2.3). The `negative` cases are ERRORs by
; design (alc rejects them). The three `known gap` cases are shapes alc accepts that this grammar still
; ERRORs on, pinned so a change to them is seen (B7b-3 task-6-report.md). `1: ;;` is a known
; OVER-acceptance unchanged from main (rule 4.2.3: keep today's behaviour). The five cases after it are
; invalid in every configuration (alc AL0104/AL0224, most also AL0111) but parse clean under the case-separator
; rules: classified over-acceptances, deferred-work item 44 precedent (spec 4.2.4); their expected trees come from
; the 0.27 CLI because they are the trees we accept. Verdicts: tools/alc_probe/cases/b7b3/case/.

================================================================================
B7b-3 case negative: a bare semicolon in case_body (alc AL0104/AL0224; Phase 0 only-semi)
:error
================================================================================
codeunit 1 P
{
    procedure M()
    begin
case I of
;
end;
    end;
}
