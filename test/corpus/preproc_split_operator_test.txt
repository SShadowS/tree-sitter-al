================================================================================
An OPERATOR alone in a #if arm: the operand follows #endif
--
`1 #if X + #endif 2` puts only the OPERATOR inside the branch. alc 18.0.41,
four-way (tools/alc_probe/cases/oracle-negative/split-operator.al): with X
defined it is `i := 1 + 2` and alc ACCEPTS it, split and flat; with X
undefined it is `i := 1 2` and alc REJECTS it (AL0104/AL0111). The parser
does not evaluate conditions, so it builds the one tree for both; the X=0
configuration is classified negative in tools/config_oracle/fixture-classes.tsv.
.
Until B3 (2026-10-01) this file was preproc_split_operator_negative_test.txt
and pinned an ERROR: the tail rule's arms had to hold `operator operand`
pairs. preproc_conditional_expression_tail now has a second form whose arms
hold ONE operator each, with the operand after #endif, so a chosen arm still
reads `operator operand ...` and the oracle's expression_tail lowering is
unchanged. Same hosts as the first form. The operator field is an anonymous
`+` here, so it does not print; cases 3 and 4 pin it where it is named.
================================================================================

codeunit 50203 D { procedure P() var i: Integer; begin i := 1
#if X
 +
#endif
 2; end; }

================================================================================
An operator alone in a #if arm: the operand after #endif is a whole expression
--
`2 + 3` is ONE operand (the greedy `_expression`), as after the first form's
`#endif`. The oracle flattens and recomposes the chain by the alc precedence
table, so with X it compares against flat `1 * 2 + 3` = `(1 * 2) + 3`.
================================================================================

codeunit 50206 D
{
    procedure P()
    begin
        Message(Format(1
#if X
            *
#else
            div
#endif
            2 + 3));
    end;
}

================================================================================
An operator alone in a #if arm: a keyword operator (mod, xor) is not a statement
--
Before B3 both statements parsed CLEAN and WRONG: no tail rule matched, so the
#if became a statement-level preproc_conditional_statement holding `mod` (or
`xor`) as an identifier STATEMENT, and `2` (or `true`) was a loose statement
after #endif. Zero ERROR nodes. alc reads `7 mod 2` and `b xor true` with X
defined. Now both are the tail's operator-only form, operand after #endif.
================================================================================

codeunit 50207 D
{
    procedure P()
    var
        i: Integer;
        b: Boolean;
    begin
        i := 7
#if X
            mod
#endif
            2;
        b := b
#if X
            xor
#endif
            true;
    end;
}
