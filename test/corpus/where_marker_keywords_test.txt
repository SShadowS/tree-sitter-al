================================================================================
where() markers are distinguishable: field(N), const(N), upperlimit(N), filter(N)
--
All four produced BYTE-IDENTICAL subtrees before 4.0.0 except filter(), which
was already a named filter_keyword sitting in the same choice() as the other
three. `where_condition` showed only `field: identifier` and `value: identifier`
with nothing recording which marker was written.
--
This is a semantic misread, not a cosmetic one. const(N) is the literal N;
field(N) is the value of field N in the current record; upperlimit(N) is a range
bound. Three different queries against the database, one tree. The assertion
here is that the four subtrees now DIFFER.
================================================================================
