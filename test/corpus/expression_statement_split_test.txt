; B6 (roadmap, spec docs/superpowers/specs/2026-10-06-expression-statement-narrowing-design.md
; section 5.2): GLR-adversarial splits around the narrowed _expression_statement. Every
; expected tree was written by hand from the FLAT reading (each configuration resolved) and
; then compared with the parser, never taken from `tree-sitter test -u`. A continuation arm
; must stay inside the assignment's preproc_conditional_expression_tail; it must never
; detach into a statement (`or (D)` as a call to `or`, `+ 2` as a unary statement). Where
; `;` closes the assignment before `#if`, the calls in the arms are statements.
