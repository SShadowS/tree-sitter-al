Issue #39: an empty #if between a then-branch and else stays in the if
--
The issue's repro. Before the fix the if_statement ended at First(), the
group was a sibling statement and `else` a call_statement named `else`, with
no ERROR. alc accepts FEATURE=0 and FEATURE=1, split and flat
(tools/alc_probe). The assertion is the else_keyword and else_branch: ON the
if_statement, with the group between them.
================================================================================
codeunit 50100 Demo
{
    procedure Run(Ready: Boolean)
    begin
        if Ready then
            First()
#if FEATURE
#endif
        else
            Second();
    end;
}

Issue #39: with no else after it, the empty group stays a sibling statement
--
The other reading of the declared conflict [$.if_statement]: here the `;`
after #endif decides, and the if has no else. A rule-wide prec.right on
if_statement would shift the group into the if and give it a MISSING else.
================================================================================
codeunit 50100 Demo
{
    procedure Run(Ready: Boolean)
    begin
        if Ready then
            First()
#if FEATURE
#endif
        ;
        Second();
    end;

================================================================================
Issue #39: a dangling else after an empty group binds to the innermost if
--
The else shifts on static precedence (prec(1)), not prec.right: this pins
that it still goes to the nearest unmatched if.
================================================================================
codeunit 50100 Demo
{
    procedure Run(A: Boolean; B: Boolean)
    begin
        if A then
            if B then
                First()
#if FEATURE
#endif
            else
                Second();
    end;
}
