(b) area_section.type and action_area_section.type -- declared but absent
--
The misleading manifestation. Every keyword branch was a bare kw(), but both
lists end with `$.identifier` as future-proofing, and that fallback kept the
field alive in node-types.json with type ['identifier'] alone. A consumer
reading the schema was told `type` exists, then got None for every real page,
because no real page takes the fallback branch. Worse than a plain omission,
and invisible to a static grammar-vs-node-types scan -- only the dynamic half
of the query-coverage harness catches it. The fallback is deliberate and stays.
