(b) area_section.type and action_area_section.type -- declared but absent
--
The misleading manifestation. Every keyword branch was a bare kw(), but both
lists end with `$.identifier` as future-proofing, and that fallback kept the
field alive in node-types.json with type ['identifier'] alone. A consumer
reading the schema was told `type` exists, then got None for every real page,
because no real page takes the fallback branch. Worse than a plain omission,
and invisible to a static grammar-vs-node-types scan -- only the dynamic half
of the query-coverage harness catches it. The fallback is deliberate and stays.

================================================================================
interface access is a body property -- the sixth site was deleted, not fixed
--
This case used to pin `interface IPub Access = Public { }`, a HEADER form, and
assert `access_value: (public_keyword)` on it. The note it carried already
recorded that alc rejects that input; it was kept anyway "for consistency".
That was the wrong call, and detector 8 caught it: over BC.History's 15,358
files `interface_declaration.access_value` was populated ZERO times, because no
valid AL can populate it. alc 18.0.33 on both spellings:
    interface I Access = Internal { }           -> AL0104 "'{' expected"
    interface I extends B access = Internal { } -> AL0104 "',' expected"
The clause is gone from grammar.js as of this commit, so the header form is now
an ERROR -- pinned in interface_access_negative_test.txt.
What AL actually writes is a body property, which the generic `property` rule
already handled all along. That is what this case pins now, for all four access
levels, so the shape is asserted to be the SAME for each. `Public` reached
`(identifier)` and the other three reached a keyword node until `public_keyword`
was added to `option_member` in this same commit.
================================================================================
interface IPub
{
    Access = Public;
    procedure P();
}
interface IInt
{
    Access = Internal;
    procedure Q();
}
--------------------------------------------------------------------------------
