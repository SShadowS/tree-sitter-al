; B7b-1 Task 11: #if groups in variable-declaration name lists `A, B: T;` (family var_names,
; grammar.js strictConditionalList). The list is the names up to the `:`; variable_declaration keeps its
; `type` field, and the label and TextConst arms are unchanged. A name inside an arm is `name:` on
; preproc_conditional_var_names, not on the declaration.
; The first 19 cases are the shapes of b7_gap_var_names_test.txt that now parse, name text unchanged,
; in their B7a route (inside `#if TPL2` of a var section, preproc_conditional_var). `MIXED` cases are
; accepted by alc in one configuration and rejected (AL0104/AL0107/AL0198, syntax) in the other: the
; split source parses, the invalid configuration is the config oracle's to judge (spec section 3).
; An empty group directly before a declaration in a var section is not part of it: it stays a sibling
; preproc_conditional_var (the tree it had before; dynamic precedence, grammar.js var_names).
; That attachment depends on the context: only at var_body top level does a sibling reading exist.
; Inside a preproc_conditional_var arm, in a split var section tail, and when the empty group is
; nested in another group at top level, the empty group is a preproc_conditional_var_names on the
; next declaration (each was an ERROR before Task 11). The "empty group context" cases pin all four.
; Attributed declarations with groups belong to Task 12 (scanner).
; Trees are hand-written from the flat reading, never copied from parser output.
