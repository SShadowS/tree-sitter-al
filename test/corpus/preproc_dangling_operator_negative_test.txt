DELIBERATE NEGATIVE -- a #if condition ending in and: the next line is not its operand
--
This file was a TRIPWIRE until B3 (2026-10-01): it pinned the WRONG tree,
condition = (preproc_and_expression FOO BAR), with the operand absorbed across
the newline and zero ERROR nodes. alc rejects every case here with AL0629
(AL0631 for the unopened parenthesis), in every configuration, with all symbols
defined so that the continuation reading would compile:
tools/config_oracle/probe_alc.py dangling_*, unbalanced_*_paren_rejected.
.
The scanner's opener_line_is_malformed now refuses an #if/#elif line whose last
condition word before any `//` is and/or/not, or whose parentheses do not
balance, so the whole directive line is one ERROR. The ERROR is the assertion;
what follows it is error recovery and not pinned for its own sake.
The valid mirror -- the operator dangling before a #if, on a CODE line -- is
preproc_dangling_operator_continuation_test.txt and stays clean.
================================================================================

codeunit 50500 X
{
    procedure P()
    var
        i: Integer;
    begin
#if FOO and
BAR
        i := 1;
#endif
    end;
}
