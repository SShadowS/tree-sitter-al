; B7b-1 (spec docs/superpowers/specs/2026-10-07-b7b-1-strict-conditional-lists-design.md):
; a #if group may stand anywhere in field_list, the comma list of a key, a fieldgroup, an addlast
; modification and a split key header. Expected trees are HAND-WRITTEN from the flat reading (the
; item list with each arm read as an alternative item run). field_list is unfielded: its raw items
; and the items inside an arm of preproc_conditional_field_list_items carry no field. Separators are
; anonymous. Comments sit in the smallest visible node holding tokens on both sides of them.
; The first 19 cases are the shapes of the former test/corpus/b7_gap_key_fields_test.txt `:error`
; witnesses, list text unchanged, on the route alc probed (addlast; tools/alc_probe/cases/b7-audit/
; key-fields__*__{gap,overaccept}.al). The four "right after the fixed ;" cases are the empty and trail shapes
; of the former b7_gap_fieldgroup_header_test.txt and b7_gap_key_header_test.txt (header text unchanged):
; a group between the fixed `;` and the first item is the list's first element. A fifth, the fieldgroup
; MIXED trail case, is the over-accept witness of fieldgroup-header / trail (B7b-1 Task 13). `MIXED` cases are accepted by alc in one configuration and rejected in the
; other (manifest tools/b7_audit/b7b1-manifest.tsv): the split source parses, the invalid
; configuration is the config oracle's to judge (spec section 3).
; addlast's field list is optional: alc accepts `addlast(DropDown; )` (B7b-1 Task 2, route
; key-fields / addlast_fieldgroup_modification, empty-interior); key and fieldgroup keep a required
; list (AL0306, semantic). The addfirst case records a CLASSIFIED OVER-ACCEPTANCE, not a fix: alc has
; no addfirst in fieldgroups at all (AL0104), and field_list is shared with addlast.
