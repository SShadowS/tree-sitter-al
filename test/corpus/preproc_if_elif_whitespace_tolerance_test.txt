================================================================================
`# if` with a single horizontal space — now scanner-exclusive (v3.2.0). The
external scanner's PREPROC_OPEN consumes '#', optional horizontal whitespace,
then the case-insensitive 'if' keyword as ONE token (scanner.c), so this
participates in the depth counter exactly like unspaced `#if`. No grammar
literal fallback exists for this token (preproc_if: $ => seq($.preproc_open,
...)) — see the design note in .superpowers/sdd/task-4-report.md for why a
scanner/literal split (the reverted 3.1.0 attempt) is a categorical GLR trap
and scanner-exclusive ownership is the only safe route.
================================================================================

codeunit 50000 "If Test"
{
    # if CLEAN24
    procedure Test()
    begin
    end;
    # endif
}

================================================================================
`# elif` with a single horizontal space, alongside no-space `#if`/`#endif`
controls (which must keep working unchanged). preproc_elif has NO external-
scanner token — unlike `#if`/`#endif` it touches no depth state, so the spaced
variant is added as a plain grammar literal (mirroring the pre-existing,
long-safe `preproc_else` spaced-literal pattern), not a scanner route. This is
NOT a scanner/literal split: there is no scanner token for elif to fork
against.
================================================================================

================================================================================
DEPTH-CORRECTNESS PROOF: a spaced `# if`/`# endif` nested INSIDE an unspaced
`#if`/`#endif`. The scanner's depth counter must increment for the outer open,
increment AGAIN for the inner spaced open, decrement for the inner spaced
close, then decrement for the outer close — landing back at depth 0. Proven
structurally: `Before`/`After` (outside any #if, depth 0) get NAMED
begin_keyword/end_keyword; `Inner` (inside BOTH #if levels, depth 2) gets
anonymous begin/end (scanner declines BEGIN_KEYWORD/END_KEYWORD at depth > 0,
so code_block has no children at all for it) — if the inner spaced open/close
failed to touch the depth counter (the exact bug class the reverted 3.1.0
literal-variant attempt introduced), Inner's begin/end would be wrongly named,
or After's would be wrongly anonymous (permanently off-by-one for the rest of
the file)
================================================================================

codeunit 50000 "Nested If Test"
{
    procedure Before()
    begin
    end;

    #if OUTER
    # if INNER
    procedure Inner()
    begin
    end;
    # endif
    #endif

    procedure After()
    begin
    end;
}

as `#if` — horizontal-only tolerance, never a cross-line match. The CRLF
variant (`#\r\nif`) shares this exact proof and was verified empirically via a
standalone (uncommitted) `tree-sitter parse` scratch fixture rather than here,
for the same `.gitattributes` `eol=lf` normalization reason documented in
pragma_whitespace_tolerance_test.txt — a committed CRLF fixture would silently
become this LF one on checkout, which is not honest coverage

================================================================================
NEGATIVE: `#iendif` must NOT be recognized as `#endif`. The '#' dispatch used
to try `if` and then `endif` with two separate walking matches; the failed
`if` attempt consumed the 'i', the `endif` attempt then matched the REMAINING
`endif` and returned true, and the result was a preproc_close spanning all
seven bytes of `#iendif`, with the depth counter decremented, exit code 0 and
no ERROR node. One buffered read of the directive word cannot do that.
================================================================================

codeunit 50000 "If Test"
{
    procedure Test()
    begin
#if CLEAN24
        Foo();
#iendif
    end;
}
